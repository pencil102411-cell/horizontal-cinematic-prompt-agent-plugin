# 设计思路

## 目标

在 Windows 电脑上，用确定性的文件系统规则给视频素材命名，并在文件还没有复制完成、仍被剪辑软件占用或目录权限异常时保护原文件。

## 核心模型

每个镜头文件夹是一个独立命名批次。文件夹名是业务前缀，字母后缀只表示同一镜头文件夹中的文件顺序：

```text
SP-0401-10\原视频.mp4      -> SP-0401-10-A.mp4
SP-0401-10\第二个.mov      -> SP-0401-10-B.mov
```

已经符合规则的文件保留；新文件从未占用的最小字母开始分配，超过 Z 后使用 AA、AB。

## 稳定文件判定

后台服务每轮只记录文件的大小和最后修改时间。第一次看到文件只建立观察记录；下一轮两个值仍然相同，并且文件可以用 `FileShare.None` 打开时，才把它放入改名计划。这能避开正在复制的文件和被剪映、剪辑软件或预览器读取的文件。

## 事务式改名

一批文件先完成全部目标路径检查，再使用唯一临时名分两步改名。任意一步失败时，服务尝试把临时名和已完成的目标名恢复为原名。每个批次先写入 `Planned` 历史记录，成功后写入 `Completed`，服务重启时可以根据磁盘状态补记未完成的记录。

## 中央 watcher

中央 runner 负责循环、日志和全局互斥锁；模块负责目录识别、稳定性、排序、命名计划和事务。计划任务只负责在用户登录时启动、在异常退出后重启。使用 UNC 路径而不是盘符，避免映射盘只对某个用户会话可见。

## 隔离异常目录

共享目录中可能出现单个无权限目录、暂时断开的目录或被服务器锁定的目录。扫描器在读取每个镜头文件夹时捕获枚举异常，写入警告并继续处理其他文件夹。这个边界很重要：一个坏目录不应该让整个生产目录停止命名。异常目录仍需由服务器管理员单独修复权限或删除。

## 安全边界

- 只处理白名单视频扩展名。
- 只处理白名单目录结构。
- 不删除、移动、转码或覆盖视频内容。
- 重复启动通过命名互斥锁收敛为一个实例。
- 日志和历史记录留在服务目录，不写入视频文件夹。
- 任务配置不包含服务器账号密码；共享权限由操作系统管理。
