# 镜头可见性与隐性矛盾审计

这份指南检查提示词里“写了什么”与“当前镜头实际上能看见什么”是否一致。它与生成前质检共用同一个独立上下文审核代理，不另起一个会重复读取全文的代理；脚本只提供保守的疑点提示，不能自动把提示词判为通过。

## 先建立镜头可见性契约

审核代理先从固定约束和时间轴为每个连续镜头提取一份内部契约：

1. **视点**：景别、机位高度、观察方向、焦距、机距、是否连续镜头或明确切镜。
2. **可见表面**：每个主体当前朝向镜头的身体/衣物/道具表面，以及哪些部位被遮挡、在画外或只作为声音存在。
3. **构图容量**：人物数量、相对位置、前后层次、画面内能容纳的细节尺度。
4. **可见动作与表演**：能被当前景别读到的动作、视线和表情；远景不把不可读的眉眼细节当作硬要求。
5. **时间状态**：该时间段结束时的人物朝向、持物、站位和伤势，供下一段接续。

每个细节都要能沿着“摄影机 → 可见表面 → 细节”解释。无法走通这条证据链的细节要标为疑点，不能用“模型会理解”跳过。

## 必查的矛盾类别

- **景别—细节冲突**：中景/中近景/双人关系镜头要求读取眼内反光、瞳孔、眉眼或面部微表情，且没有明确的推近、切镜或主观视点。
- **朝向—表演冲突**：背影、背对镜头、侧后方遮挡却直接描写同一主体的面部表情、正脸五官或口型；只有明确写出回头、转身并给出时间段，才可作为状态变化处理。
- **机位—可见表面冲突**：镜头从人物背后/遮挡物后方观察，却要求看到被遮住的胸前、手中物或正面伤口。
- **固定视点—切镜冲突**：同镜连续、固定机位或一镜到底与“切到特写/另一个角度/跳切”并存，且没有明确的镜内变焦或重新建立视点。
- **人数/关系—细节归属冲突**：双人镜头中的眼神、反光、手部或道具没有说清属于谁，导致模型交换主体或凭空增加第三人。
- **时间状态冲突**：前段背对、持剑、站在左侧，后段突然出现正脸、空手或换位，且没有动作过程、遮挡或切镜作为原因。
- **素材证据—文字冲突**：引用的资产只提供背面/远景/遮挡视图，却把不可见的正面细节写成已确认事实。

## 处理顺序

1. 先以用户锁定的景别、机位、朝向和连续性为硬约束。
2. 再把不可见细节改成当前镜头可执行的结果：例如改为重心、肩背张力、手部动作、轮廓光或声音反应。
3. 若细节本身不可替代，给它一个最小的合法视点变化：明确推近/变焦/回头/切镜、起止时间和状态接续；不要只加“清晰看到”四个字。
4. 不为修复矛盾擅自改台词、剧情结果、人物身份或用户冻结的镜头顺序；无法同时成立时报告冲突和两个最小修复选项。

## 报告格式与门槛

每条疑点报告：`冲突 ID → 时间段/原文证据 → 摄影机为何看不到 → 对成片的可能影响 → 最小修复建议`。脚本 `scripts/check_visibility_conflicts.py` 的 `REVIEW_REQUIRED` 只表示发现需要解释的词面组合；`NO_AUTOMATIC_FINDING` 也不表示语义通过。独立子代理必须逐条决定“通过 / 问题 / 未检 / 不适用”，并把结论绑定到最终正文 SHA-256。

修改景别、机位、朝向、表演、时间轴或相关素材后，原可见性审计立即失效；只要受检正文或接点变化，就必须用新版本重新审查。主代理不能以“脚本没有发现”替代独立子代理，也不能把未运行、超时或证据不足写成通过。
