# 本地场次记忆

## 什么时候使用

当用户在一个具体场次项目目录中调用本插件，并要求建立、读取、更新、保存或继续使用场次记忆时，执行本规则。

场次记忆固定保存为当前场次项目根目录下的 `场次记忆.md`。用户给出明确项目路径时使用该路径；否则使用当前工作目录。项目位置已经明确时直接执行，不重复询问。

## 建立记忆

1. 查看当前项目里的分镜或剧本、资产目录以及用户补充要求，只读取建立记忆所需的内容，不修改原文件。
2. 若 `场次记忆.md` 不存在，按 `templates/场次记忆模板.md` 创建；能从现有文件确认的信息直接填写，不能确认的内容留空或写“待确认”，不猜测。
3. 若文件已经存在，先完整读取，在原文件上合并更新，不覆盖已有有效内容。
4. 用户只要求建立记忆文件时，完成文件后停止，不顺带生成提示词。

## 更新记忆

在同一场次的提示词制作和返修过程中，遇到以下信息时直接更新本地文件：

- 用户明确说“记住”“以后都保持”“后面的提示词都要有”或同义要求。
- 用户要求继承上一条的人物动作、站位、表演状态、道具状态、光影或环境状态。
- 用户根据生成结果指出反复出现的问题，并说明了有效改法。
- 用户要求取消、替换或修正已经记录的要求。

默认作用范围只限当前场次。单镜头的一次性调整不自动写成整场规则；用户明确要求记录时可以写入，并标明镜号。

新要求与旧要求冲突时，以用户最新明确要求为准，直接修改“当前有效要求”或“连续性状态”，不要让互相冲突的版本同时有效。已验证的失败与改法用一行记录在“优化经验”，避免堆积完整对话。

“保持上一条”不能作为最终状态原样保存。能够从上一条提示词、成片或用户描述中确认时，展开为具体的人物位置、朝向、姿态、动作阶段、视线、表演强度和道具状态；确实无法确认且会影响下一条时，再问一个必要问题。

每次写入后，只需告诉用户已更新的文件路径和新增或改变了什么；除非用户要求，不在对话中重复输出整份文件。

## 本地边界

- 只读写当前场次项目里的 `场次记忆.md`。
- 不把内容写入本 Skill、插件仓库、`references/`、Codex 全局记忆或其他项目。
- 不自动提交 Git、上传网络或同步给其他人。
- 文件中的记录只对当前场次有效，不能当作其他场次或其他作品的规则。
