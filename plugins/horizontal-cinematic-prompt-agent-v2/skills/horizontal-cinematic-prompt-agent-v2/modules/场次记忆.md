# 本地场次记忆

把当前场次的有效要求、采用版本、镜头接点和制作进度保存在一份场次记忆文件中（默认名 `场次记忆.md`），方便继续制作。它是本场的制作备忘录，不是插件规则库或完整聊天记录。

## 定位与启用

用户要求建立、读取、更新或继续使用场次记忆，或本场已有已启用的记忆文件时，按本指南处理。首次建立需用户明确说“建立场次记忆”“保存这场的要求”或同义要求；普通生成、一次返修或衔接上一条，不自动新建文件。

文件放在当前场次项目根目录。优先使用用户明确的项目路径，否则使用当前工作目录。结合已有资料核对作品、集数或场次、适用目录；信息已明确就直接执行，不重复询问。

**文件名与多场共用一个目录**：

- 用户明确指定的记忆文件（路径或文件名）优先使用，不要求改名，照样核对归属；对不上本场时指出差异，问一个问题，确认前不写入。
- 一个目录只做一场时，用默认名 `场次记忆.md`；已知要放多场时，第一场也可直接用带标识的名字。同一目录之后新增的每一场，命名为 `场次记忆-<集场标识>.md`；原有的 `场次记忆.md` 保持原名，不擅自改名。
- 集场标识：《风起玲珑骨》用索引的 `scene_id`，例如 `场次记忆-E03-S012.md`。`scene_id` 按出场顺序编号，部分场次与剧本场号（索引的 `scene_label`）不同（第 2、3、5、7 集共 60 场），须先查索引换算，例如第 3 集剧本第 10 场是 E03-S012；文件「场次信息」里两者都写。其他项目沿用用户的集号和场号写法，去掉文件名里不允许的字符（`\ / : * ? " < > |`），空格改成短横线；没有集号只写场号；同一场始终用同一个标识。
- 新建或读取前，先列出目录里所有场次记忆文件（`场次记忆*.md` 及用户指定的文件），按各文件「场次信息」里的作品、集数／场次认出属于本场的那份；旧格式文件没有这一栏时，按文件里能看出的作品和场次判断。已有属于本场的文件就沿用，不另建。
- 多份文件都属于本场时，不自动合并、改名或删除；先只读，问用户以哪份为准。认不出归属且会串戏时，也只问一个必要问题，并先完成不依赖它的工作。
- **每场单独授权**：每一场首次建立记忆，都需要用户针对这一场明确提出；另一场已有记忆或已开启“本场持续维护”，不等于这一场获得授权。
- 已有文件属于另一场时，不套用、不覆盖。用户要求跨场接戏（例如下一场接上一场的伤势、服装）时，可以读另一场的记忆作参考，内容经用户确认后才进入本场。
- 首次建立后，在回复里写明文件的完整路径。

建立时按 `templates/场次记忆模板.md` 填入已知内容；非关键缺项留空或标“待确认”，不为填表编造信息。旧格式文件仍可使用，只在获准更新时补充本轮需要的栏目，不要求先迁移、重建或填满模板。

## 维护方式

在文件中记录本场的维护方式：

- **明确维护（默认）**：用户说“记住”“后面保持”“继承这个状态”，或明确更正、取消已记录内容时直接更新，不重复索要建立授权。只要求读取或普通一次返修，不自动写入。
- **本场持续维护**：用户明确说“这场持续维护记忆”或同义要求后，在本场后续工作中保存确认的要求、选定版本、接点与实际制作进度，不要求每次再说“记住”。尚未采用的创意只在确有续做需要时记为待定，不进入有效要求。

本场还没有记忆文件时，用户说“记住”，也不把本场内容转存到宿主程序的记忆（除非用户明确要求存进宿主记忆）；说明可以建立场次记忆，或只在本次对话里沿用，不虚报“已记住”。缺少维护方式的旧文件按“明确维护”处理。用户暂停维护后停止自动写入，已有有效内容仍可按需读取；用户明确要求不再使用记忆时，也停止继承。普通单镜调整即使需要记录，也只作用于该镜，不自动扩大为全场规则。

## 记清五件事

1. **是哪一场**：作品、集数或场号、适用目录及必要的剧本和资产位置。沿用已有名称和镜号，不强制新建编号体系。
2. **保持什么**：具体有效要求、作用镜号或全场范围，以及必要来源。保留影响画面、表演、光影和衔接的细节，不压缩成抽象标签。
3. **采用哪一版**：用户已选定的图片、视频或提示词文件及版本；素材只控制已明确的身份、外观、空间等内容。没有版本号可记选定文件名，未选定则标待定，不按生成时间或文件修改时间自动换版。
4. **下一条怎么接**：按镜号或关键时间点记录具体位置、朝向、姿态、动作阶段、视线、表演强度、持物和环境状态，只写影响后续的内容。
5. **做到哪里**：区分提示词已完成、候选已生成、用户已选定、成片已核验，记录待返修事项和下一步。它们是进度说明，不是每条必须依次完成的审批流程；待办也不授予自动执行后续镜头的权限。

## 设计目标与实际接点

**设计是否批准，与成片是否实现，分开记录。** 提示词只能证明设计内容；用户说“这个方案定了”不等于动作已经生成。用户对「本轮读取清单」的确认只针对读取范围，不算设计批准。分别记“设计目标／批准情况”和“实际观察／依据”。没有成片依据时标为“预计，待验证”，仍可继续设计下一条，不强制先补视频。

实际状态的依据可以是亲自查看的成片、用户明确描述的结果或对应项目资料。标明来源；关键接点附采用文件、版本及必要的秒数或帧位置。用户描述的结果不能写成自己已看片核验；文件路径存在本身也不能证明画面内容。用户已选定的版本不重复询问是否采用。

“保持上一条”应展开为具体状态。状态按场次、镜号或故事时点，以及已有的方案分支区分；维护日期不决定剧情先后。镜 2 握瓶与镜 5 放瓶可以同时有效，返修前镜不能用“最新状态”覆盖后镜。区分角色自身左右、画面左右和场景方位；稳定光源绑定窗门等场景位置，正反打后按机位转换画面受光方向。

用户改变设计目标时，保留当前成片观察，并更新目标和待返修事项，不用旧成片阻止改稿。前镜终态或采用版本变化时，只检查依赖该变化的后镜接点；需要时标记待复核，不自动重写整场。

## 读取与续做

先确认本场归属，读取续做摘要和本场有效要求，再取当前镜号、相关接点及必要的变更记录。短文件可全文读取；较长时按栏目和镜号定位，但不能漏掉适用于全场的要求，也不必每轮重读全部旧过程。

只有仍有效、适用于当前镜号和方案的内容才被继承。待定建议不升级为事实，已被替代的内容不再约束创作。记忆的有效内容（用户确认、选定版本、已核验接点、已批准的设计终态）与剧本不一致时，按 `AGENTS.md`「冲突时听谁的」执行：沿用记忆并提示差异，不悄悄改回剧本。缺少非关键资料时继续完成当前请求；仅关键接点矛盾会实质改变交付时才澄清。

## 更新与保存

更新前读清原文件和相关有效内容，在原件上合并本轮变化，保留其他有效要求。对同一对象、作用范围、故事时点和方案中的冲突，以用户最新明确要求替代旧要求；重要替代简记原因，旧条目退出有效区。全场要求与单镜例外可并存，例如“全场无泪，镜 7 除外”，不能为消除表面冲突而抹掉其中的适用范围。

重复信息不重复追加。优化经验只保留有依据的问题、有效改法和适用条件，未验证尝试留待定；变更记录保留必要理由，不堆积聊天或每轮快照。用户撤回要求时不再继承；明确要求删除记录内容时，从本文件的有效区、经验和变更记录中一并清除对应内容，不把它复制到历史区继续保留。

写入前若发现文件被其他任务改动，重新读取并合并，避免用旧副本覆盖；这项检查不等于已经实现多人并发锁。写后回读确认改动落盘且其他有效内容仍在，再简短报告路径和变化。没有新变化时无需写入，也不重复输出整份记忆。

读取或保存失败时，不猜旧内容、不用空模板覆盖原件、不虚报“已记住”。按当前已有输入继续完成能独立交付的创作，并说明本次未成功读取或保存。暂停维护或保存失败不等于暂停制作。

用户只要求维护记忆时，交付文件与变化即可；同时要求生成或返修时，继续完成该部分。五区块格式只用于最终视频提示词。已保存的文件可用于后续续做，但不承诺宿主会在每次压缩前自动保存或在所有新任务中自动加载。

## 本地边界

- 记忆的写入目标只有当前场次项目中属于本场的那份场次记忆文件（下一条的宿主记忆例外除外）；可读取本场必要的剧本、资产和成片作为依据，不修改这些原件。
- 不把本场记录写入本 Skill、插件仓库、`references/`、任何宿主程序的全局或长期记忆（例如 Codex 全局记忆、Claude Code 的 memory 目录，以及用户目录或项目目录里由宿主自动加载的 CLAUDE.md、AGENTS.md；用户明确要求把某些内容存进某个宿主记忆的除外，只存用户点名的内容）或其他场次，不把本场改法升级为通用规则。
- 不因创作或记忆维护自动提交 Git、上传网络、同步给其他人，也不自动建立历史附件、数据库或后台服务。
- 检查或升级插件本身属于另一项任务，须有用户对此明确授权；本场记忆维护不提供该授权。
