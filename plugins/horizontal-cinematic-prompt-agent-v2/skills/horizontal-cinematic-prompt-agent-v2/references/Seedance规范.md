# Seedance 2.0 生成规范 — 横屏真人影视

> 所有 skill 共享的模型能力参考与提示词写法，按当前任务需要调用。用户本轮明确要求和已确认事实优先，具体裁决见 `AGENTS.md`。本文件的四区块、时间轴和字数要求只适用于最终视频提示词，不限制讨论、诊断、方案比较或插件维护。

## 一、模型能力与使用入口

**适用版本与核验记录：** 以下公开能力依据 Seedance 2.0 模型官方介绍，不代表每个应用入口具有相同上传配额、人物素材政策或开放功能。来源：[Seedance 2.0 官方发布页](https://seed.bytedance.com/zh/blog/official-launch-of-seedance-2-0)，发布于 2026-02-12，本次核验日期 2026-09-07。官方展示 15 秒多镜头生成，也说明多主体交互、口型与细节仍有改进空间。

| 项目 | 当前工作依据 |
|------|--------------|
| **生成时长与多镜头** | 以官方支持的 15 秒多镜头能力为依据，本项目默认按每条 4—15 秒组织；用户提供的实际平台限制或已验证能力优先 |
| 图片、视频、音频参考的数量与时长 | 按用户使用入口的当前界面或官方文档确定；本次未做各入口上传配额核验，不把历史数字写成所有平台的硬限制 |
| 写实人物素材上传 | 按具体平台的当前政策与可用功能处理，不作跨平台统一禁止的判断 |
| 一致性与执行效果 | 用实际可用的参考素材、明确的身份与连续性描述提高一致性；不承诺每次生成均能准确执行 |

**拆条规则：** 按实际入口时长上限和用户要求安排生成条数。沿用本项目默认入口时，超过 15 秒的内容按有效叙事或动作切点拆条，并在代码块外写清拆点；连续各条沿用适用的资产、空间关系、光位和状态变化。不要因“复杂”这个笼统理由拆散本可连续完成的镜头；用户要求逐镜生成、明确的物理断点或实际生成失败也可成为调整组织方式的依据。

### 运镜与切镜设计

以下是可优先尝试的创作手法，**保留其叙事功能和画面力度，不将任何一项写成必定成功的能力承诺**：

| 类型 | 说明 |
|------|------|
| 复合运镜 | 可组合推/拉/摇/移/升降/环绕，如“拉+旋转+焦点转移”；写清同一摄影机的路径、速度与焦点交接 |
| 条内切镜 | 一条提示词可包含多个镜头；明确切点和承接状态，不把切镜误称为单镜内部无切点运动 |
| 长镜动作 | 单镜可设计连续多个攻防回合；交代双方目标、空间和受力因果，保留长镜的完整动作体验 |
| 大幅度运镜 | 如特写起幅→拉起上摇→鸟瞰全景→平移跟人；明确路径、视差与途中可见内容，检查机位是否能够连续到达 |
| 变速 | 可设计实速与慢动作的节奏转换，明确观众在慢下来的阶段需要看清什么 |
| 特效密度 | 可设计多发生点和多层粒子；按作用顺序、空间分层与主次关系描述，避免无因果的效果堆叠 |
| 短镜 | 1—2 秒镜头可用于清楚的单个信息或动作落点；它是视频条内的镜头时长，不等于单次生成时长 |

**调整依据：**

- 不凭“模型可能撑不住”等未经验证的泛化判断主动削弱镜头。先检查叙事、物理连续性和观看顺序；有实际失败画面、用户反馈或具体能力限制时，再针对根因优化，并说明对效果的影响
- 区分“拆镜”和“拆条”：拆镜改变剪辑，拆条改变生成任务。先采用能保留镜头意图的局部修改，再判断是否需要改变镜头或条数
- 当前入口没有可核实控制接口的帧率、升格倍率、分辨率等，不作为精确执行承诺写进提示词；改写为“能看清什么”的视觉结果。动作次数或转体角度确有叙事作用时可以保留，但要有清楚的起止姿态与落点，不用数字替代画面描述

## 二、提示词核心公式

```
【风格】+【素材引用】+【主体动作/状态】+【景别/精确焦距/景深】+【机位/运镜】+【光影动机】+【环境运动与反馈】+【稳定性约束】
```

**关键原则：有素材则引用，缺资料则区分已知与设计。** 已有角色/场景资产及环境信息时直接沿用，不重复索要；已看过的图用于身份、形制和空间参考，当前时间、天气、伤势及光照状态按用户明确要求处理。时间轴补充动作、情绪、光线，不重复无用的五官、发型或建筑描述。用户要求先出时可用具名占位引用；未见图的灯具、窗位、服装细节不能写成已确认事实，必要导演假设在代码块外说明。

## 三、时间轴组织

最终视频提示词用时间轴交代画面与状态变化。**一条视频**对应一次生成，可含多个镜头；**一个镜头**是切点之间连续的摄影机观察；**时间段**用于标记一个镜头或其中的状态变化；**节拍**是动作、信息或情绪的一次推进。一个镜头可以包含有因果的多个动作和节拍，不要求每拍另切一镜。

每个镜头交代适用的**景别/焦距/机距/透视/景深 + 机位/运镜或固定观察 + 可见画面 + 主体动作或状态 + 相关环境反馈**。普通镜头选一个精确焦距；明确镜内变焦时可写起止值及可见变化，详见 `references/镜头与灯光词典.md`。空镜描写景物和变化，不强加人物表演；室内静态环境或稳定光线可明确保持，不为填字段制造风、光动和粒子。

时长按用户指定值或已有逐镜时长之和安排；缺少时长时默认以 15 秒作为工作基准继续，在代码块外说明。只有时长会实质改变必须保留的内容且无法合理安排时，才提出一个关键问题；不重复询问已有信息。

### 15秒示例结构

```
0-3s  ：开场建立（景别 + 入画 + 环境初态）
3-8s  ：发展/爆发（主体动作展开 + 运镜推进 + 核心事件）
8-12s ：高潮/转折（画面重心变化 + 关键动作/反馈）
12-15s：收束/落版（余波 + 环境回落）
```

> 这是时间组织示例片段，不是完整交付，也不是必须复制的四段模板。台词密度、动作节拍、情绪转折点决定实际切分；缺时长采用 15 秒工作基准时也不必照抄这里的切点。

### 按镜头可见内容选择运动层

| 层级 | 内容 | 示例 |
|------|------|------|
| 主体运动 | 角色动作、表情变化 | 主角迈步前行、汗水滑落、瞳孔收缩 |
| 环境运动 | 天空、云、光影、风 | 云层缓慢飘动、树叶摇曳、光影移动 |
| 背景运动 | 人群、物体、粒子 | 人群快速移动、落叶飘散、尘埃飞扬 |
| 特效运动 | 火花、雨滴、烟雾 | 火花飞溅、雨水顺着屋檐滴落、烟雾扩散 |

上表是选项，不要求每段凑齐四层。室外风、雨、雪、雾或尘与镜头相关时，写清其本体变化和至少一项实际可见作用；画面同时容纳人物、场景、道具或光影的不同层时，可写两类反馈帮助建立受力因果。特写只写能看见的层，空镜不补人物，保持方向、湿度与累积状态连续。细则见 `references/室外环境动力.md`。

### 错误格式（禁止）

❌ 景别与构图互相矛盾、❌ 机位路径或切点不明、❌ 已写天气却没有任何可见作用、❌ 时间段衔接状态冲突。固定机位、稳定光线和无人物空镜本身不属于错误。

## 四、景别与运镜速查

### 景别

| 景别 | 画面范围 | 适用场景 |
|------|---------|---------|
| 远景 | 广阔空间，环境为主 | 开场建立场景、命运感 |
| 全景 | 人物全身 + 环境 | 展示人物与环境关系 |
| 中景 | 人物膝上 | 对话、双人动作 |
| 近景 | 人物胸上 | 表情变化、情绪传递 |
| 特写 | 面部/局部 | 关键情绪、证据、道具 |
| 主观视角 | 角色第一人称 | 沉浸感、紧张感 |

### 运镜/转场

| 方式 | 说明 | 情绪功能 |
|------|------|---------|
| 固定镜头 | 相机不动 | 压迫、观察、让表演发生 |
| 推镜头 | 相机向前 | 强调、心理压力增加 |
| 拉镜头 | 相机后撤 | 展示环境、孤立感 |
| 摇/移镜头 | 横向/纵向移动 | 展示空间、跟随 |
| 跟镜头 | 跟随主体移动 | 跟随运动、连续性 |
| 环绕 | 360度旋转 | 展示主体、被包围感 |
| 硬切 | 直接切换 | 节奏紧张 |
| 渐变 | 淡入淡出 | 情绪过渡 |
| 叠化 | 画面重叠 | 回忆、时间流逝 |
| 升格 | 慢动作 | 强调动作、情绪 |
| 降格 | 快动作 | 时间压缩 |

## 五、多模态引用语法

有资产图时的标准引用格式：

```
@图片1 作为玲珑的固定形象参考，保持玲珑的面部、发型与本场已确认服装一致
@图片2 作为六象宫帝鸿书房正打方向的空间结构参考；本场光照按【光影设计】执行
@图片3 作为黎奴骨鞭的形制与材质参考，保持该骨鞭的骨节结构和相对尺寸一致
@视频1 参考围绕玲珑从侧面移至正面的摄影机路径，实际起止机位按本条时间轴执行
```

> 以上是素材引用示例片段，不是完整提示词。资产名可替换为实际平台编号，但说明文字中的人物、场景和道具身份必须保留。默认不主动添加 BGM、字幕或音频参考；用户明确要求时按实际入口能力处理。

## 六、稳定性约束词库

> **这是词库，不是必写清单。** 最终固定约束以 `templates/标准输出模板.md` 为起点，按用户要求和本镜实际设计判断适用性。特效戏的空间异变需要环境崩解，手持震动需要镜头抖动；删去或限定冲突的通用约束，保留其余必要的身份与连续性约束。

### 主体约束
`人物面部特征保持一致，不扭曲，不换脸，肢体比例自然`

### 场景约束
`没有剧情触发的场景结构与物件位置保持连续，环境变化按时间轴发生，不出现无因果的闪烁或突变`

### 动作约束
`动作起止、重心与接触因果清楚，不出现无意卡顿、穿插或反关节；动作幅度、瞬移或变形按本镜明确设计执行`

### 镜头约束

`镜头切换处角色形象、光位方向与色温、画面左右关系保持一致`

> 切点约束用于保持应连续的身份、光位与空间关系。不要把“平滑无抖动”作为所有镜头的默认口号；稳定推镜可要求平滑，手持震动则保留受控抖动。环绕、第一人称飞行、变速、跳切和构图改变是否适用，按各自镜头意图判断，不互相替代或一概排除。

### 光影色彩约束
`光源、阴影与曝光保持因果连续；固定光照段稳定，法术、遮挡、天气或人物移动引起的光变按时间轴发生`

### 音频约束
`不输出背景音乐，画面不带字幕；角色台词正常出声，口型与台词严格对上`

> 默认不主动加 BGM/字幕，与角色说话无关。有出声台词时写清说话人、语气与口型同步目标；画外音按剧本处理，不要求未出镜角色显示口型。对口型是作品验收要求，不是模型必定成功的承诺。

## 七、提示词字数约束

提示词写给 Seedance 2.0 视频模型，不是说明书也不是给人看的。每条文字最终输入模型时都必须有用。

| 场景复杂度 | 上限 |
|-----------|------|
| 简单戏（日常对话、单人物反应、固定场景） | ≤2000字 |
| 复杂戏（双人对峙、文戏推进、情绪变化） | ≤3000字 |
| 最复杂戏（特效爆发、多人混战、多段运镜混合） | ≤4000字 |

**统计口径：只算【素材引用】+【时间轴】两个区块，标点不计。**

固定约束与光影设计不计入本项目这项字数预算；光影依然承担叙事与连续性作用，不能因“不计数”无限堆写。画幅与时长没有独立输出区块。以上是本项目的编辑预算，不是已核验的所有平台输入上限。

### 上限是天花板，不是目标

这是**上限**，不是配额，更不是需要努力靠近的字数目标。判断标准永远是「这句话模型生成画面时用得上吗」——用得上就写，写完自然收尾，剩多少余量都不用管；用不上就删，哪怕远没到上限。

> 上限从 1000/2000/3000 上调到 2000/3000/4000，是为了给必要的动作、表演和连续性留下空间，不是要求把额度写满，也不是拿去堆运镜、环境和形容词。

### 信息优先级（重点，别再写浅）

有人物承担叙事的镜头里，**主体行为包含动作与表演**。常见的写坏方式是把预算全花在景别和运镜上，人物只剩一句“她神情复杂地看着他”。应写可见行为，不用抽象标签代替表演；空镜、物件插入或看不见面部的镜头，不为完成表演字段增加不存在的人或微表情。

按“主体行为与表演 → 镜头关系 → 必要环境反馈”的顺序分配文字。主体必须写清，但不设固定字数占比；简单动作不为凑篇幅增加无意义微表情，复杂表演也不能被景别和运镜描述挤掉。

**表演层的硬要求**（细则与词库见 `skills/情感表演.md`）：

- **镜头中的叙事人物使用可执行表演**，不能只写“情绪化地”“神情复杂地”“眼神一冷”这类抽象标签；按可见景别选择视线落点、咬肌、呼吸、指尖或重心等适用表现，不要求每个部位同时变化
- **情绪必须有因果**：写清基线、触发和可持续终态；没有变化的克制表演可以保持稳定，不强行制造一次表情反转
- **配得上景别与对象**：人物近景/特写写镜头看得见的表演；手部、伤口、兵器等插入镜头写关键动作、材质或信息；远景大全景优先重心、步态、距离和群体关系
- **控制尺度和通道数量**：每个状态只保留一个主变化和至多一个辅助泄露；先确定泪态，删除互相冲突的表情与动作

**其余规则：**
- 不得为遵守字数而刻意缩写或省略必要信息导致画面质量下降
- 提示词中的每段文字都必须是 Seedance 2.0 模型生成画面时需要的指令
- 不写背景说明、设计意图、创作思路、前情摘要等模型不需要的内容
- **技术参数要有实际依据**：默认把“2—4帧微定格”“120fps”“20—30倍升格”等改成可见停顿、运动速度和细节清晰度；只有用户所用入口确实支持对应控制时，才按其接口设置，不把提示词中的数字当作执行保证

## 八、提示词写作原则

| 原则 | 说明 |
|------|------|
| 目标导向 | 提示词是给模型的生产指令，不是设计说明。不写模型不需要知道的背景信息 |
| @引用优先 | 人物/场景/道具/运镜特征通过 @资产 引用传递，不由文字重复描述 |
| 连续推进 | 一条视频可含多个镜头，一个镜头可含多个有因果的动作；按观众需要理解的节拍组织，不混写无关情节或前情总结 |
| 每个字必须有用 | 不写背景说明、设计意图、创作思路等模型不需要的内容 |
| 中文主干 | 主体描述一律中文；只有布光、运镜、材质、VFX 四类专业术语按「中文（English keyword）」附英文 |
| 只写可执行的 | 模型能生成画面的才写，帧率倍率之类的后期参数不写 |
